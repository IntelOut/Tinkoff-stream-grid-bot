# Торговый бот для Тинькофф Инвестиции (Grid Trading)

Асинхронный сеточный торговый бот для Тинькофф Инвестиции с использованием библиотеки `t-tech-investments`.

## Описание стратегии

Сеточная торговля (Grid Trading) - это стратегия, при которой бот выставляет сетку лимитных ордеров выше и ниже текущей цены:

- Ордера на продажу выше текущей цены
- Ордера на покупку ниже текущей цены

При исполнении любого ордера бот автоматически выставляет противоположный ордер на соседнем уровне сетки, поддерживая постоянное количество активных ордеров.

## Возможности

- Асинхронная архитектура на одном gRPC-канале
- Сеточная торговая стратегия
- Автоматическое восстановление пропущенных ордеров
- Точечная отмена ордеров только по своему инструменту (не затрагивает ордера других инструментов счета)
- Переподключение торгового стрима при разрыве соединения
- SQLite база данных (WAL) для сохранения состояния
- Корректная обработка цен через Decimal (без потери точности nano)
- Поддержка Docker
- Конфигурация через переменные окружения
- Подробное логирование

## Установка

### Локальная установка

1. Клонируйте репозиторий:

```bash
git clone <repository-url>
cd <project-directory>
```

2. Создайте виртуальное окружение и установите зависимости:

```bash
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements.txt --extra-index-url https://opensource.tbank.ru/api/v4/projects/238/packages/pypi/simple
```

3. Настройте окружение:

```bash
cp .env.example .env
```

Заполните `TINKOFF_TOKEN` в файле `.env` (токен можно получить в личном кабинете Тинькофф Инвестиций).

### Запуск

```bash
python tinkoff-stream-grid-bot.py
```

Остановка: `Ctrl+C`.

## Запуск в Docker

```bash
docker build -t grid-bot .
mkdir -p data
docker run --env-file .env -e DATABASE_PATH=/app/data/sqlite_bot.db -v "$(pwd)/data:/app/data" grid-bot
```

Каталог `data` монтируется в `/app/data` для сохранения базы данных и лога между перезапусками контейнера (не перекрывая код приложения). На Linux убедитесь, что хост-каталог доступен на запись пользователю с UID 1000: `sudo chown -R 1000:1000 data`. Либо используйте именованный volume: `-v grid-data:/app/data`.

## Конфигурация

### Переменные окружения (`.env`)

| Переменная | Описание | По умолчанию |
|---|---|---|
| `TINKOFF_TOKEN` | API-токен Тинькофф (обязательно) | - |
| `TINKOFF_ACCOUNT_ID` | ID счета. Если не задан - используется первый счет | - |
| `DATABASE_PATH` | Путь к файлу базы данных SQLite | `sqlite_bot.db` |
| `ORDER_CHECK_INTERVAL` | Интервал проверки ордеров, сек | `60` |
| `GRID_LEVELS` | Количество уровней сетки по умолчанию | `6` |
| `PRICE_STEP` | Шаг цены по умолчанию (доли цены, `0.01` = 1%) | `0.01` |
| `QUANTITY` | Количество лотов по умолчанию | `1` |

### Торгуемые инструменты

Бот ищет инструменты среди всех типов: акции, облигации, ETF, валюты и фьючерсы. Список инструментов задаётся в `GridBotConfig.shares_config` в файле `tinkoff-stream-grid-bot.py`:

```python
self.shares_config = {
    "btcusdperpa": {
        "levels": 5,          # Количество уровней сетки
        "price_step": 0.0001, # Шаг цены в долях цены
        "quantity": 1,        # Количество лотов в ордере
        "start_price": 0,     # Начальная цена (0 - использовать текущую рыночную)
    },
}
```

Для каждого инструмента из конфига бот находит его в API по тикеру (в каталогах акций, облигаций, ETF, валют и фьючерсов), получает минимальный шаг цены и строит сетку уровней, симметричную относительно стартовой цены. Уровень, ближайший к текущей рыночной цене, пропускается (ордер на него почти мгновенно бы исполнился). При совпадении тикеров приоритет отдается акциям, затем облигациям, ETF, валютам и фьючерсам.

## Как работает бот

1. При старте бот инициализирует инструменты, строит ценовые уровни и сохраняет их в SQLite.
2. Отменяет старые ордера по своим инструментам (по одному, по ID из БД - чтобы не задеть ордера других инструментов) и выставляет новую сетку.
3. Подписывается на стрим исполненных сделок (`trades_stream`). При исполнении ордера выставляет противоположный на соседнем уровне.
4. Каждые `ORDER_CHECK_INTERVAL` секунд проверяет количество активных ордеров и восстанавливает недостающие.

Если замещающий ордер не удалось выставить (сетка вышла за границы или ошибка API), ордер помечается исполненным, и уровень будет восстановлен периодической проверкой.

## Ограничения и риски

- Бот не отслеживает открытую позицию: при перезапуске сетка перестраивается относительно текущей цены.
- Нет ограничения суммарной экспозиции - количество денег под риском определяется числом уровней и количеством лотов.
- Используется на свой страх и риск; перед реальной торговлей рекомендуется тестирование на песочнице.
